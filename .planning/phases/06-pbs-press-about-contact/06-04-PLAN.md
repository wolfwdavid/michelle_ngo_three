<objective>
Close the single Phase 6 verification gap: the D-16 chrome-fade does NOT fire on `/press` during scroll.

Root cause (confirmed by 06-VERIFICATION.md frontmatter + source reading): `TopNav.svelte` attaches the scroll-idle listener via a querySelector that matches ONLY the ReelStage container label `[role="region"][aria-label="Filmography reel"]`. `/press` renders a bespoke scroll container labeled `aria-label="Press credits reel"` (it does NOT use ReelStage), so the querySelector returns `null` on `/press`. TopNav then falls back to `initScrollIdle(window)` — but `/press` scrolls its inner `overflow-y-auto` container, not `window`, so `onScroll` never fires, `scrollIdle.isScrolling` never flips true, and the `$derived chromeClass` never appends `opacity-0 pointer-events-none`.

Fix: broaden the querySelector to a CSS selector-list that matches EITHER reel container label. Exactly one such container exists per route, so the selector-list resolves unambiguously. This is a one-line change inside the existing `$effect` (plus a one-line comment update). The route-scope half of D-16 (`/press` ∈ `REEL_ROUTE_IDS`, line 65) is already wired and unchanged.

Purpose: Make the cinematic chrome-fade behave consistently across all four reel routes (`/work`, `/work/[category]`, `/pbs-american-portrait/`, `/press`) — the D-16 contract.
Output: One-line edit to `src/lib/components/TopNav.svelte`; `press.spec.ts` Test D passing on chromium + webkit + firefox.
</objective>
