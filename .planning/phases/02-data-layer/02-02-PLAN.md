<objective>
Add a `drift-check` job to the existing `.github/workflows/deploy.yml` workflow that fails the build whenever `_three`'s `videos.json` drifts from the `_four` commit pinned in `.videos-source-sha`. Runs on every PR and on every push to main.

Purpose: Implements DATA-04 / Trap A mitigation. A `_three` PR that accidentally edits `videos.json` (or forgets to refresh the sidecar after a sync) is rejected before merge. This is the cross-repo A/B-integrity precondition: if `videos.json` drifts, the A/B compares two different catalogs and the result is invalid.

Output: One updated `.github/workflows/deploy.yml` with a new `drift-check` job (sibling to `build` and `deploy`) and the workflow `on:` triggers expanded to include `pull_request`.
</objective>

    ```yaml

      drift-check:
        # DATA-04 / Trap A mitigation. Fails the workflow if src/lib/data/videos.json
        # has drifted from the _four commit pinned in src/lib/data/.videos-source-sha.
        # Runs on every PR and every push to main (D-10). Lives in this single workflow
        # file per D-11 (no separate drift-check.yml).
        runs-on: ubuntu-latest
        steps:
          - name: Checkout _three
            uses: actions/checkout@v4

          - name: Read pinned _four SHA from sidecar
            id: pin
            run: |
              set -e
              SIDECAR=src/lib/data/.videos-source-sha
              if [ ! -f "$SIDECAR" ]; then
                echo "::error::Missing $SIDECAR — Plan 02-01 must create it before drift-check can run."
                exit 1
              fi
              FOUR_SHA=$(grep '^four_commit_sha=' "$SIDECAR" | cut -d= -f2)
              if [ -z "$FOUR_SHA" ] || [ ${#FOUR_SHA} -ne 40 ]; then
                echo "::error::Invalid four_commit_sha in $SIDECAR (expected 40-char hex, got: '$FOUR_SHA')"
                exit 1
              fi
              echo "four_sha=$FOUR_SHA" >> "$GITHUB_OUTPUT"
              echo "Pinned _four SHA: $FOUR_SHA"

          - name: Checkout _four at pinned SHA
            id: checkout_four
            continue-on-error: true
            uses: actions/checkout@v4
            with:
              repository: wolfwdavid/michelle_ngo_four
              ref: ${{ steps.pin.outputs.four_sha }}
              path: __four
              # Public repo — no token needed. fetch-depth: 1 is the default.

          - name: Handle unreachable _four SHA (D-07 force-push case)
            if: steps.checkout_four.outcome == 'failure'
            run: |
              echo "::error::_four@${{ steps.pin.outputs.four_sha }} no longer reachable. Re-sync from _four's current main and update src/lib/data/.videos-source-sha (refresh four_commit_sha, videos_json_sha256, synced_at)."
              exit 1

          - name: Byte-compare videos.json against pinned _four
            run: |
              set -e
              FOUR_FILE=__four/src/lib/data/videos.json
              THREE_FILE=src/lib/data/videos.json
              if [ ! -f "$FOUR_FILE" ]; then
                echo "::error::Expected $FOUR_FILE after checkout but it is missing. _four's repo structure may have changed."
                exit 1
              fi
              if cmp -s "$FOUR_FILE" "$THREE_FILE"; then
                echo "videos.json byte-identical to _four@${{ steps.pin.outputs.four_sha }} ✓"
                exit 0
              fi
              # D-12 failure message — EXACT wording (names file, names SHA, gives literal cp command):
              echo "::error::videos.json drift: src/lib/data/videos.json does not match _four@${{ steps.pin.outputs.four_sha }}. Re-sync: cp ../michelle_ngo_four/src/lib/data/videos.json src/lib/data/videos.json && update src/lib/data/.videos-source-sha (refresh four_commit_sha, videos_json_sha256, synced_at). Then commit and push."
              # Surface a short diff snippet for the PR reviewer (first 20 differing lines):
              diff -u "$FOUR_FILE" "$THREE_FILE" | head -40 || true
              exit 1

          - name: Verify sidecar sha256 matches the local file (catches accidental local edits)
            run: |
              set -e
              SIDECAR=src/lib/data/.videos-source-sha
              RECORDED=$(grep '^videos_json_sha256=' "$SIDECAR" | cut -d= -f2)
              ACTUAL=$(sha256sum src/lib/data/videos.json | awk '{print $1}')
              if [ "$RECORDED" != "$ACTUAL" ]; then
                echo "::error::Sidecar sha256 mismatch: $SIDECAR records videos_json_sha256=$RECORDED but the actual file's sha256 is $ACTUAL. Update the sidecar after editing videos.json (refresh videos_json_sha256 and synced_at)."
                exit 1
              fi
              echo "Sidecar sha256 consistent ✓"
    ```

    **Important details:**
    - Use `actions/checkout@v4` exactly (matches Phase 1 versions; D-09 specifies v4).
    - The `path: __four` clones into a sibling directory inside the workflow runner's workspace — does NOT collide with `_three`'s source tree (the runner's workspace is ephemeral).
    - `continue-on-error: true` on the `Checkout _four at pinned SHA` step is essential so the next step can emit the D-07 force-push error message instead of GitHub's generic checkout failure.
    - Do NOT modify the existing `build:` or `deploy:` jobs.
    - Do NOT add the new job inside the `build:` job — it MUST be a sibling job so branch protection can require it independently.
    - The error annotation message in the byte-compare step MUST contain the literal string `videos.json drift:` and the literal `cp ../michelle_ngo_four/src/lib/data/videos.json src/lib/data/videos.json` command (D-12 exact wording).

    **Subdirectory name** (Claude's discretion per CONTEXT §Claude's Discretion): `__four/` chosen. The double-underscore prefix makes it visually obvious it's a vendored-at-runtime checkout, not part of `_three`'s source tree. Alternatives `tmp/_four/` or `external/_four/` are equally valid — executor stays with `__four/` for consistency with the comment in the action.

    **Decision references:** D-09 (`actions/checkout@v4` second clone), D-10 (PR + push triggers), D-11 (single workflow), D-12 (exact error wording), D-07 (force-push fix-it message).
